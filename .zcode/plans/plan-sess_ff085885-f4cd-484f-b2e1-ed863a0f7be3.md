阶段 1：隔离复现取证（全部用临时目录 + TestClient + 故障注入，不碰真实实例/真实数据/隧道配置/端口 8000/18000）

1. 隧道发布失败根因验证（最高优先）
   - 用 TestClient 向写接口注入 Origin=https://公网域名 + Host=localhost:8000 的请求，验证是否全站写请求 403（预期成立）；对照组 Host=公网域名 应放行；补 sec-fetch-site 变体与无 Origin 老浏览器行为。
   - 注册连坐：模拟同一来源 IP（隧道下人人都是 127.0.0.1）连续注册至限额，验证整班 429 的触发条件与窗口参数。
2. 剩余 B1 写接口故障注入（patch store.save_async 注入一次失败）
   - change-password：503 后旧密码/新密码各是什么表现、会话是否已删、用户是否被卡死。
   - register：503 后重试是否 409 registration_conflict，学生是否无法重新提交。
   - enrollment approve/reject、courses enroll/remove：503 后重试是否 404/409。
   - practice submit：503 后重试是否 409（对照已修复的 quiz submit）。
   - delete_user / delete_document：验证"先物理删文件、后落盘"，503 后文件已删而记录会在重启后复活指向缺失文件（临时目录文件实证）。
   - chat ask：503 后回答是否已入历史、配额是否已扣（重试双计费）。
3. 学期规模性能补测
   - 挂学期规模合成 store（约 20MB JSON），TestClient 实测单个写请求端到端延迟（中间件等待全量落盘）；excel 快照路径的锁内 deepcopy 计时。
4. 前端 401 行为取证
   - Node VM 提取前端 apiRequest/submitQuiz/草稿函数，模拟会话过期（401 响应），记录：无跳转登录、成绩区只显示"请先登录"、草稿保存静默失败等具体表现。
